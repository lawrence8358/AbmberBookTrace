# 專案背景文件

工程技能在開始探索程式碼前，應該先讀取這些文件：

- 專案根目錄的 `CONTEXT.md`
- 專案根目錄的 `docs/adr/`
- 如果存在 `CONTEXT-MAP.md`，就按照它找到相關的 `CONTEXT.md`

如果這些檔案還不存在，請安靜地繼續工作，不要特別提醒，也不要一開始就要求建立它們。

## 檔案位置

這是一個單一背景的專案，檔案大致如下：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-某個重要決定.md
│   └── 0002-另一個重要決定.md
└── src/
```

`CONTEXT.md` 會記錄專案使用的專有名詞和重要背景。

`docs/adr/` 會記錄重要的設計決定。開始修改某個部分前，請先讀取和它有關的 ADR。

## 使用專案自己的名詞

在問題標題、重構建議、假設和測試名稱中，請使用 `CONTEXT.md` 裡的名詞。

不要自己換成看起來差不多的說法。如果需要的名詞不在裡面，可能表示專案需要補充背景文件。

## 發現衝突時

如果你的建議和現有的 ADR 不一致，請清楚說明，不要直接忽略原本的決定。

例如：

> 和 ADR-0007 的決定不同，但因為某個原因，可能值得重新討論。
